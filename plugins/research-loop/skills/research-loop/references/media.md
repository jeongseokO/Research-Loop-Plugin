## Figures and attachments

Follow [Visual explanations](visual-explanations.md) when choosing and explaining a visual. Keep its reading, research meaning and limits accessible beside it and in the final reply; a file or widget alone is not the explanation.

The upload tools are in the media group, outside the tool list: `call_tool_write` calls the uploads and `call_tool_read` calls `get_research_media`; `describe_tools(group:"media")` lists them.

For literature, first inspect and reuse informative original paper figures/tables following `get_guide(topic:literature)`: authorized source, faithful extraction, readable labels, attribution and explanation nearby. Preserve original embedded text; do not redraw a paper figure just to remove it. If access, reuse or extraction is unavailable, identify the missing visual and give its source and grounded explanation.

Before making a new image, check whether the page can draw it: a measured comparison is the table itself with `table.chart` (a grid of conditions in one unit is its heatmap), a mechanism or experiment design is an explainer block (`get_guide(topic:writing, section:explainer)`), and a derivation uses an equation block (`section:equation`). These stay editable and keep their rendering tied to structured inputs. Upload only what they cannot hold: distributions of many samples, maps too large for a table (attention, saliency), photographs, paper-ready static figures. For those, read `get_guide(topic:visualization, section)` for the relevant technique; static method figures use the bundled [method-figure skill](../../method-figure/SKILL.md). Generate from verified data/structure. In either case, visually inspect the actual local image before uploading. Research Loop stores images, not rendered plots from arbitrary code. Never fabricate measurements or report a placeholder as completed.

Before upload, keep only essential labels, axes, units, legends, data values or mechanism symbols in a new figure. Move explanatory sentences, conclusions and commentary boxes to the real page block `caption` and nearby prose as needed. Text in canvas margins, titles or annotations is still inside the image; do not bake in a caption. Alt text is separate, not a replacement for the visible caption. This does not authorize erasing text from original paper figures.

1. Call `prepare_research_media_upload` with the file name, actual size and SHA-256, within current server limits.
2. PUT the exact bytes to its private `uploadUrl` with Content-Type and **no additional Authorization header**. The bundled [upload helper](../../../scripts/upload-image.mjs) takes the prepare response through stdin and the local file path as its argument, keeping the URL out of command-line arguments. It validates the fixed Research Loop Storage destination.
3. Call `complete_research_media_upload` with `upload_id`. After an uncertain PUT, try completion before preparing a duplicate upload. Reuse the prepare key only for the same file and metadata.
4. Attach the returned permanent `media` reference with caption and alt text after rereading the target page. Upload success alone is not a page save; protected saves may still require review.

A picture that already exists on the web (a paper's own figure, a real apparatus or photograph) is brought, not redrawn: `call_tool_write` with `import_research_image`, the image file's https address (`image_url`, its src) and the page it appears on (`source_url`). The server fetches both, reads the licence where it can and returns an image block with `source`; add an id, alt text and a caption that says whose picture it is, keep `source`, and save. Use it only when the reader needs the original, prefer CC or public-domain pictures (Wikimedia Commons), and never present someone else's picture as evidence for our results.

A plot drawn from data with the research-plot helper keeps how it was made: put `figure_record(...)`'s result in the plot block as `made` (data and code by repository-relative name with SHA-256, commit, tool, look, slot, date); the page shows it under the caption. Keep `made` when re-saving the page; leave it out when the image file is replaced. A figure for a deck is drawn in the deck's look with `slide_context`; see the [research-plot usage](../../research-plot/references/usage.md).

Prefer binary upload to base64 in model context. `upload_research_media` is a fallback only for files within its smaller limit. Export unsupported figure formats to PNG. To inspect an existing attachment, read its page, then use `get_research_media` with its attachment block ID. Upload and download URLs are temporary credentials: never save them in content, logs or final responses. Do not delete historical, unattached or pending-review assets as cleanup.
