# Research Loop plugin

프로젝트 · 연구 페이지 · 실험 · 문헌 · 일정 · 마감 · AI 작업

[Research Loop](https://research-loop.lukeo112.chatgpt.site/)에 ChatGPT·Codex·Claude Code를 연결하는 플러그인입니다. 지원되는 ChatGPT 화면에서는 연구 페이지를 읽고 편집하면서 대화를 이어갈 수 있습니다. 웹앱 소스와 연구 데이터는 포함하지 않습니다. GitHub 배포와 OpenAI Plugins Directory 심사·게시는 별개이며, Directory에는 아직 게시되지 않았습니다.

## Codex 설치

[단계별 AI 연결 안내](CONNECTION-GUIDE.md)를 따라 설치하세요. VS Code의 출처·Git ref·Sparse 입력값, CLI 설치, OAuth 로그인, 프로젝트 접근 요청과 오류 해결을 함께 정리했습니다. [웹에서 안내 보기](https://research-loop.lukeo112.chatgpt.site/guide/ai)

사용 예:

- “내 Research Loop 프로젝트 현황을 보여줘.”
- “Research Loop를 열고 이 페이지를 함께 다듬자.”
- “이 실험 결과를 기존 페이지에 표로 추가해줘.”
- “이 프로젝트의 마감을 확인하고 다음 주 계획을 만들어줘.”

기존 개인용 `research-loop@personal`을 사용 중이라면 두 플러그인을 동시에 켜지 마세요. 공개판의 연결을 확인한 뒤 기존 개인용 플러그인을 해제합니다. 이 저장소는 기존 설치나 API 키를 자동 변경하지 않습니다.

## Claude Code 설치

[AI 연결 안내의 Claude Code 절차](CONNECTION-GUIDE.md)를 사용하세요. 플러그인과 MCP 직접 연결 중 하나만 선택합니다. 설치는 서버 접근 승인을 대신하지 않습니다.

## 업데이트

0.25.0은 **계획과 AI 협업을 플러그인 내부 화면**으로 제공합니다. 주별 일정·마감·미팅에서 할 일을 구체화하고, 프로젝트 AI 작업의 담당 상태·최근 보고·결과 기록과 토론을 확인합니다. 계획 검토, 작업 분해, 중복·막힘 점검, 토론 정리를 요청문으로 준비한 뒤 명시적으로 ChatGPT에 보낼 수 있습니다. 현재 AI가 맡을 수 있는 대기 작업은 최신 권한과 상태를 다시 확인하고 선점한 뒤 진행합니다. 다른 AI를 자동으로 실행하거나 상태를 반복 조회하지 않습니다. 개인 포트폴리오 작업·비공개 캘린더는 프로젝트 화면에 섞지 않습니다. 대응 MCP 버전은 0.35.0, 화면 리소스는 `workspace-v3.html`이며 이전 화면 주소도 호환됩니다.

0.24.0은 **Open Research Loop 내장 작업 화면**을 연구 홈과 **할 일 → 근거 → 공유 준비** 흐름으로 정리합니다. 할 일의 목적·완료 기준과 연결된 기록을 먼저 확인하고, 주간 업데이트·미팅 발표의 뼈대를 일반 노트 초안으로 시작할 수 있습니다. 초안은 사용자가 검토하고 명시적으로 저장해야 하며, 팀 전체 진척을 자동 수집한 보고서는 아닙니다. 저장한 페이지는 **발표 보기**에서 슬라이드 목차와 방향키로 발표할 수 있습니다. 발표는 저장된 전체 문서의 읽기 전용 화면이며 PPTX 파일 내보내기는 포함하지 않습니다. 기존 페이지 편집·ChatGPT 요청·권한·검토 정책은 유지됩니다. 대응 MCP 버전은 0.34.0이며, 새 화면 리소스는 `workspace-v2.html`입니다. 이미 열어 둔 화면은 다시 열어야 할 수 있습니다.

0.23.1은 MCP 서버·Open Research Loop 도구·내장 화면과 플러그인에 Research Loop 로고를 제공합니다. SVG를 표시하지 않는 환경에서도 사용할 수 있도록 기존 로고의 PNG를 함께 제공합니다. 대응 MCP 버전은 0.33.1입니다.

0.23.0은 팀 작업 연결을 보강합니다. 웹사이트의 **할 일 → 이번 주 공유**에서 진행 기록 기반 초안을 만들고, 저장된 페이지의 **페이지 도구 → 발표 보기**로 발표합니다. 편집기에서 표를 선택해 **그래프 만들기** 또는 `/visualize`로 실제 PNG를 미리 보고 삽입할 수 있습니다(웹사이트 업로드 지원 필요). 담당 작업을 시작하기 전 AI가 진행 중으로 선점하며, 다른 AI는 사람이 인계하기 전 그 담당 기록을 덮어쓸 수 없습니다. 원격 Codex 연결 안내는 기존 MCP 인계 방식이며 자동 실행기는 포함하지 않습니다. 대응 MCP 버전은 0.33.0입니다.

0.22.0은 **페이지 작성·편집과 ChatGPT 협업을 한 화면에서** 이어가는 흐름을 위한 패키지입니다. 대응 MCP 버전은 0.32.0입니다. 내장 작업 화면에서 새 일반 노트를 작성하고, 기존 페이지는 전체 원본을 확인한 뒤 블록 단위로 편집합니다. 선택 부분이나 저장된 페이지를 대상으로 요청을 적어 **ChatGPT에 요청**을 눌러야 대화가 시작됩니다. “쉽게 설명·구조 다듬기·근거 확인”은 요청 문구를 채워 주며 자동으로 보내거나 수정하지 않습니다.

- 저장하지 않은 수정과 새 페이지는 먼저 저장해야 ChatGPT에 요청할 수 있습니다. 페이지 전체 요청은 본문을 자동 복사하지 않고 대상과 버전을 전달합니다. 선택 부분은 최대 4,000자와 20개 블록까지 전달합니다.
- 제목과 본문은 별도 저장 작업입니다. 일부만 저장되거나 검토가 필요하면 그 상태를 구분합니다. 요청을 전달했다는 메시지는 답변 생성이나 페이지 저장 완료를 뜻하지 않습니다.
- 패널의 저장은 연결된 AI 자격으로 처리됩니다. 기존 작성자 판정·직접 수정·검토 요청 정책이 그대로 적용되며, 사람의 웹사이트 로그인 권한으로 바뀌지 않습니다.
- 첨부 파일 업로드와 지원하지 않는 페이지 작업은 원본 웹사이트에서 이어갑니다. ChatGPT Space의 native 편집기를 가져오거나 모든 기능을 동일하게 제공하는 것은 아닙니다. 실제 ChatGPT 대화와 연결하며 별도의 모델 답변을 흉내 내지 않습니다.

서버 배포·공개 패키지 게시·설치된 클라이언트의 갱신은 서로 다릅니다. 이 버전 설명만으로 어느 단계가 완료됐다고 판단하지 마세요. 자세한 사용 범위는 [내장 작업 화면](plugins/research-loop/skills/research-loop/references/panel.md)을 참고하세요.

0.21.0은 ChatGPT 내장 화면에 웹사이트와 같은 프로젝트 메뉴와 연구 분류를 제공합니다. 노트·할 일을 구분해 탐색하고, Main/Sub 관계를 보면서 본문을 열 수 있습니다. 지원되는 화면에는 넓게 보기 버튼이 표시됩니다. 최근 추가·연구 트리·계획·AI 협업은 같은 프로젝트의 웹사이트로 연결됩니다.

0.20.1은 할 일 생성·이름 변경 전에 `tasks` 작성 지침을 읽도록 연결합니다. 제목에는 구체적 대상과 행동·목적을 쓰고, 설명은 무엇을 왜 하는지부터 시작합니다. 내부 방법 코드·실행 번호 대신 독자가 이해할 이름을 사용하며, 이름 변경으로 기존 작업 범위·담당·일정·상태를 바꾸지 않습니다.

0.20.0은 대화 옆 연구 기록 패널, 입력창의 기록 검색·첨부와 선택 문단 공유를 추가했습니다. 처음에는 읽기 중심이었으며, 작성·편집 흐름은 위 0.22.0 안내를 따릅니다. 실제 메뉴 노출은 호스트의 확장 지원과 도구 새로고침에 달려 있습니다. MCP 배포와 설치된 패키지 갱신은 별도입니다.

현재 패키지: **0.25.0**. AI용 작성 지침은 영어로 제공하며, 결과물은 사용자가 요청한 언어를 따릅니다. 영어 고유명사·공식 명칭·자연스러운 전문 용어를 억지로 번역하지 않습니다. 공통 작성 디자인을 core/tasks/report/lists/annotations/evidence/review로 나눠 필요한 지침만 읽습니다. 연구 질문에서 시작하는 보고서, 주장·근거의 계층 목록, 첫 등장 용어의 클릭 주석을 적용합니다. 실험 역할(메인·Ablation·Preliminary)과 선택적인 메인 연결은 실험 작업에서만 규격을 읽습니다. 기존 실험은 자동 분류하지 않습니다. 같은 묶음의 하위 결과를 함께 종합하여 메인 보고서의 중복 작성을 줄이며, 메인 할 일 완료는 여전히 사람의 명시적 결정입니다. 팀 배정 시 역할·업무 여유와 별도 동의된 바쁜 시간을 확인합니다.

- 스킬 진입점은 핵심 도구 10개(`who_am_i`, `get_project_instructions`, `get_research_brief`, `query_research_objects`, `get_research_page`, `patch_research_page`, `save_research_page`, `create_research_object`, `get_research_tree`, `patch_research_tree`)로 이루어진 기본 흐름을 먼저 안내합니다. 나머지 도구는 현재 작업에 필요할 때만 불러오며, 도구 이름·권한은 바뀌지 않았습니다.
- 방법론 figure는 구조·상호작용·개입 위치를 드러내는 코드 기반 벡터 제작이 기본입니다. PNG·편집 가능한 SVG/벡터 PDF·원본을 보관하고, 이미지 생성은 검증 가능한 최후 수단으로만 사용합니다.
- 비교 표·plot은 높을수록 좋은 지표와 낮을수록 좋은 지표를 나눕니다. 작은 차이는 점·변화량 등 적합한 표현으로 드러내되 잘린 막대나 확대만으로 과장하지 않습니다. 기존 plot 팔레트·폰트와 자원 제한은 유지합니다.

- 연구 트리는 등록일이 아닌 실제 연구 시점을 기록합니다. 일·월·연도·기간과 근거를 보존하고, 저장 뒤 표시 날짜·관계·승인 상태를 확인합니다. 모르는 날짜를 추측하지 않습니다.
- 분석 템플릿도 공통 작성 지침을 적용합니다. 필요한 곳에 클릭형 용어 설명, 검증된 데이터셋 예시 링크와 비교 시각화를 연결합니다. 불필요한 설명은 늘리지 않습니다.
- 연구 트리는 **요약 → 관련 가지 → 근거 페이지 → 바뀐 부분만 반영** 순서로 정리합니다. `patch_research_tree`는 생략한 기록과 필드를 보존하며, Editor의 변경은 승인 요청입니다.
- 하이라이트 AI 요청은 내 AI 공용 대기열을 사용합니다. 첫 claim만 실행하고 검토 대기·완료된 요청은 중복 처리하지 않습니다.

필요한 작업 안내만 읽고 기존 시각화 스타일과 개인정보 보호 원칙을 유지합니다.

```sh
codex plugin marketplace upgrade research-loop
codex plugin add research-loop@research-loop
```

Claude Code는 `claude plugin marketplace update research-loop` 후 `claude plugin update research-loop@research-loop`를 실행합니다.

업데이트 후 새 작업을 시작합니다. 실제 계정의 설치·OAuth·권한 검증 상태는 [배포 체크리스트](RELEASE-CHECKLIST.md)를 참고하세요.

MCP 서버의 도구·작성 규격은 연결된 서버에서 제공됩니다. 플러그인은 해당 작업에 필요한 안내만 읽도록 연결하며, 매번 전체 이력이나 모든 가이드를 불러오지 않습니다. 서버 업데이트가 이미 설치된 플러그인 파일까지 교체하지는 않습니다. 위 절차는 공개판용이며, 개인용 `research-loop@personal`은 해당 로컬 원본을 갱신한 뒤 재설치해야 합니다.

하이라이트에서 보낸 AI 요청은 선택 문장과 요청사항을 함께 전달합니다. AI는 원문을 다시 확인하고 담당 작업을 claim한 뒤 처리합니다. 큐에 추가하는 것만으로 Codex·Claude가 자동 실행되지는 않습니다.

## 정량 그래프

“이 결과를 Research Loop 기본 스타일로 그려줘”라고 요청합니다. [research-plot 스킬](plugins/research-loop/skills/research-plot/SKILL.md)은 질문에 맞는 그래프를 고르고 공통 스타일·함수를 재사용합니다. 수치를 이미지 생성기로 그리지 않습니다.

- NanumSquare 우선, 없으면 설치된 대체 폰트를 확인합니다. 폰트는 동봉하거나 자동 다운로드하지 않습니다.
- 비교 대상의 색을 유지하고, 축 범위·오차 구간은 실제 데이터에 맞춥니다. 최고 모델을 자동 선정하지 않습니다.
- 기본 출력은 PNG입니다. 출판용 PDF·SVG는 필요할 때 선택합니다. 원본 코드·데이터를 보관하고 페이지 너비에서 가독성을 확인한 뒤 첨부합니다. 기존 연구 그림은 자동 교체하지 않습니다.

## 방법론 그림

“이 방법론을 overview figure로 그려서 페이지에 넣어줘”라고 요청합니다. 그림 작업에만 [method-figure 스킬](plugins/research-loop/skills/method-figure/SKILL.md)을 읽습니다.

- 검증된 방법의 실제 구성·상호작용·개입 위치를 대상에 맞는 형태로 표현합니다. 흰 배경·파랑/청록 기본 구조·주황 개입 강조, 좌→우 또는 아래→위 흐름을 사용합니다. 설명은 그림 밖에 둡니다.
- 로컬 Python·Matplotlib 또는 적절한 벡터 도구로 제작하고 PNG·편집 가능한 SVG/벡터 PDF·재생성 원본을 함께 보관합니다. 내장 실행기는 `--formats png svg pdf`로 선택합니다. 이미지 생성 모델은 기본 제작 도구가 아니며, 확인되지 않은 구조를 채우는 데 사용하지 않습니다. 환경이 없으면 [전용 환경 설정](plugins/research-loop/skills/method-figure/references/setup.md)을 확인합니다.
- AI가 실제 이미지를 확인하고 페이지에 첨부합니다. 코드만 작성·파일만 업로드한 상태와 승인 대기를 완료로 보고하지 않습니다.
- 원본 파일은 로컬 작업 폴더에 유지합니다. 웹앱에는 PNG를 넣습니다. 그림의 정확성·가독성은 AI와 연구자가 확인해야 하며 모든 모델의 실행을 보장하지는 않습니다.

MCP만 연결하면 로컬 스킬·제작 스크립트가 설치되지는 않습니다. 플러그인을 갱신하거나 사용 가능한 별도 그림 도구가 필요합니다.

## 공유 서버에서 사용

일반적인 최신화는 전체 데이터·로그 재검색이나 그림 일괄 재생성을 뜻하지 않습니다. 기존 결과를 재사용하고 필요한 작업만 순서대로 실행합니다.

- 그림 실행기: 기본 60초, 최대 120초. 같은 사용자의 동시 실행 거절, 주요 수치 라이브러리 스레드 1개. 방법론 CLI에는 자동 적용되며, 직접 작성한 plot 스크립트는 [실행기](plugins/research-loop/scripts/render_guard.py)를 통해 실행합니다.
- Plot 출력: 최대 12 MP, 240–600 DPI. 방법론 그림: 최대 8 MP. 기존 저장 이미지나 업로드의 10 MiB 한도는 바꾸지 않습니다.
- 실행기는 OS의 CPU·메모리 강제 할당량이 아닙니다. 임의 코드나 여러 서버 사용자의 총 부하는 서버 관리자 측 scheduler/container 제한도 필요합니다. 제한을 넘으면 작업을 나누고, 같은 작업을 병렬 재시도하지 않습니다.

## 권한과 지원 범위

사용자와 AI를 확인하고 프로젝트·페이지의 현재 revision을 읽은 뒤 요청된 변경만 수행합니다. Editor AI는 본인 사용자 계정이 처음 만든 일반 노트(토론·연구 트리 제외)·문헌·실험·데이터셋·결과를 직접 수정할 수 있습니다. 다른 사람의 기록과 질문·방법·주장 등 보호된 기록, 마감, 휴지통·복원, 링크·프로젝트 정보·주간 계획 변경은 검토 요청입니다. 기존 계획의 상태만 작성자 또는 수락한 담당자가 직접 바꿀 수 있으며 보관·복원은 제외됩니다. 새 기록·토론·답글은 직접 생성하지만 새 마감과 연구 트리는 검토가 필요합니다. 작성자는 생성 이력으로 확인하며 속성 편집으로 권한이 바뀌지 않습니다. 직접 수정에는 write, 보호된 수정에는 write와 propose 권한이 필요합니다. 승인된 Semi-Owner AI는 허용된 연구 내용을 직접 수정하며, 프로젝트 생애·접근 권한 관리는 Owner에게 남습니다. Viewer AI는 읽기 전용입니다. 서버가 제안으로 처리한 변경은 승인 전까지 반영되지 않습니다.

표와 문서 블록, Markdown 강조를 지원합니다. AI가 실험 데이터로 직접 plot·figure를 그린 뒤 PNG/JPEG/WebP/GIF 파일을 업로드하고 페이지에 넣을 수 있습니다. 하루 업로드 개수 제한 없이 파일당 최대 10MiB이며, SVG/PDF 그림은 PNG로 내보냅니다. 그림 생성은 연결한 AI의 실행·이미지 도구가 담당하고, Research Loop는 검증된 파일을 저장합니다.

작은 파일은 MCP에서 직접 업로드할 수 있고, 큰 파일은 임시 업로드 주소를 사용합니다. 페이지 저장 권한과 Owner 검토 절차는 그대로 유지됩니다. 업로드·다운로드용 임시 주소를 페이지에 저장하거나 공개하지 마세요.

Google Calendar 연결 및 프로젝트 선택은 웹앱의 개인 설정에서 수행합니다. MCP/AI는 Google OAuth 토큰에 접근하지 못하며, Calendar 연결·계정 관리 권한을 갖지 않습니다.
